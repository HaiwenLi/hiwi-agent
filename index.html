📋 项目总览

🎯 核心目标

构建一套个人 AI 工作流基础设施，解决跨工具的"记忆断层"和"协作割裂"问题。

解决的问题

问题描述
对话断层上次让 AI 分析的论文，下次问完全不记得
多工具割裂OpenCode / Codex / DeepSeek 之间不共享信息
工具调用繁琐每次换模型都要改代码
技能不可复用论文检索的提示词调好了，下次要用又要重写
Agent 静态绑定不同任务需要不同模型，固定绑定太死板

统一接口定义

interface ModelAdapter {
    // 模型标识
    id: string;
    name: string;
    
    // 能力描述
    capabilities: string[];  // code, writing, analysis, search...
    maxTokens: number;
    contextWindow: number;
    
    // 成本（每 1K tokens）
    costPer1kInput: number;
    costPer1kOutput: number;
    
    // 调用方法
    chat(messages: Message[], options?: ChatOptions): Promise<Response>;
    embed(texts: string[]): Promise<number[][]>;
    
    // 健康检查
    healthCheck(): Promise<boolean>;
}

🤖 多 Agent 协作系统

通信模式选择

模式适用场景复杂度例子
主从模式（Master-Slave）一个 Agent 规划，多个执行🟢 低主 Agent 分解任务 → 子 Agent 执行
对等模式（Peer-to-Peer）多个 Agent 平等协作🟡 中多个专家 Agent 讨论决策
层级模式（Hierarchical）多层级汇报，如组织架构🟡 中经理 → 组长 → 组员
事件驱动（Event-Driven）事件触发，异步协作🟢 低Observer 模式

推荐：先实现主从模式，最简单，能覆盖大部分场景。

Agent 间消息协议

// 消息格式
{
  type: "task_request" | "task_response" | "context_share" | "heartbeat",
  from: "agent_id",
  to: "agent_id" | "broadcast",
  payload: {
    task_id: "唯一ID",
    action: "what needs to be done",
    context: { /* 共享上下文 */ },
    priority: "high|normal|low",
    deadline: "ISO timestamp"
  },
  timestamp: "2026-05-12T16:00:00Z"
}

冲突处理机制

场景处理方式
两个 Agent 同时修改同一数据乐观锁 + 版本号，最终写入者获胜
任务分配不清主 Agent 决策，其他人执行
结果不一致投票机制 or 专家 Agent 仲裁
Agent 卡死超时检测 + 自动重启

🧭 自适应模型路由

核心观点：静态绑定 Agent → Model 太死板，应该根据任务动态选择最优模型。

方案 A：任务分析 + 动态匹配（推荐）

用户任务输入 │ ▼ ┌─────────────────────────────────────────┐ │ 任务分析器（Task Analyzer） │ │ - 识别任务类型（代码/写作/分析/检索） │ │ - 评估复杂度（简单/中等/复杂） │ │ - 提取关键需求（速度/准确性/成本） │ └─────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────┐ │ 模型能力矩阵（Model Capability DB） │ │ ┌─────────┐ ┌─────────┐ ┌─────────┐ │ │ │ 代码能力 │ │ 写作能力 │ │ 分析能力 │ │ │ │ 评分 │ │ 评分 │ │ 评分 │ │ │ └─────────┘ └─────────┘ └─────────┘ │ │ + 成本 + 延迟 + 可用性 │ └─────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────┐ │ 智能路由（Smart Router） │ │ 考虑权重：能力(50%) + 成本(30%) + 延迟(20%) │ │ → 输出最优模型推荐 │ └─────────────────────────────────────────┘

方案 B：级联模型（成本优化）- 默认策略

任务输入 │ ▼ ┌─────────────┐ │ Level 1 │ ← 快速模型（Haiku/GPT-4o-mini） │ 快速判断 │ 响应快、成本低 └──────┬──────┘ │ ▼ 置信度判断 │ ┌───┴───┐ ▼ ▼ 高 低 │ │ │ ▼ │ ┌─────────────┐ │ │ Level 2 │ ← 中等模型（Sonnet/GPT-4） │ │ 深入处理 │ 能力更强 │ └──────┬──────┘ │ │ │ ▼ │ 置信度判断 │ │ │ ┌───┴───┐ │ ▼ ▼ │ 高 低 │ │ │ │ │ ▼ │ │ ┌─────────────┐ │ │ │ Level 3 │ ← 最强模型（Claude Opus） │ │ │ 终极处理 │ 最高成本，最高能力 │ │ └─────────────┘ │ │ │ ▼ ▼ ▼ 输出 ←─── 最终输出 优势：简单任务用便宜模型，复杂任务自动升级 成本可降低 60-80%

方案 C：多模型投票（质量优先）

任务输入 │ ├─────────────────┬─────────────────┐ ▼ ▼ ▼ ┌────────┐ ┌────────┐ ┌────────┐ │Model A │ │Model B │ │Model C │ │Claude │ │DeepSeek│ │ GPT-4 │ └───┬────┘ └───┬────┘ └───┬────┘ │ │ │ ▼ ▼ ▼ 结果 A 结果 B 结果 C │ │ │ └───────────────┼───────────────┘ ▼ ┌─────────────┐ │ 结果整合器 │ │ - 一致性检查 │ │ - 冲突解决 │ │ - 综合输出 │ └─────────────┘ │ ▼ 最终答案 适用场景：重要决策、高风险任务、论文分析

方案 D：学习型路由（长期优化）

系统会记录每次任务使用的模型和结果评分，持续优化选择策略。

// 自适应模型路由配置
{
  "router": {
    "strategy": "cascade",  // 默认策略
    "fallback_strategy": "vote",  // 降级策略
    
    "cascade": {
      "levels": [
        { "name": "fast", "models": ["haiku", "gpt-4o-mini"], "confidence_threshold": 0.8 },
        { "name": "medium", "models": ["sonnet", "gpt-4"], "confidence_threshold": 0.6 },
        { "name": "strong", "models": ["opus", "gpt-4-turbo"], "confidence_threshold": 0 }
      ]
    },
    
    "capability_weights": {
      "accuracy": 0.5,
      "speed": 0.2,
      "cost": 0.3
    },
    
    "learning": {
      "enabled": true,
      "min_samples": 10,  // 至少10个样本才开始学习
      "decay_factor": 0.95  // 旧数据权重衰减
    }
  }
}
